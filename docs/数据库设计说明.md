# 谷盒 GrainBox · 手办/谷子收藏管理平台 —— 数据库设计说明

> 依据《软件需求规格说明书 GRAINBOX-SRS-001 V1.0》第 5 章
> 技术栈：Supabase（Auth + PostgreSQL + RLS + Storage + 视图/函数/触发器）+ 原生 HTML/CSS/JS

---

## 一、系统定位

谷盒是一个「以作品系列为主线的私人收藏图鉴 + 轻量统计工具」。不卖东西、不做物流、不做社交关系链，只解决三件事：我的藏品有哪些、它们属于哪个系列、我为它们花了多少钱。

数据模型围绕 **系列 → 藏品 → 收藏记录** 三层展开；界面围绕 **看图鉴、管收藏、看统计** 三条动线展开。

## 二、概念模型（E-R）

共识别 5 个实体、4 个联系，落地为 **7 张表**（5 实体表 + 2 中间表）：

```
profiles(用户) ──M:N── items(藏品)        → collections 中间表（带状态/价格等属性）
series(系列)   ──1:N── items(藏品)
tags(标签)     ──M:N── items(藏品)        → item_tags 中间表（联合主键）
items(藏品)    ──1:N── item_images(图片)
```

「收藏」是一个**带属性的联系**：用户与藏品之间是多对多，且这条关系本身需要记录状态、价格、渠道，因此在逻辑设计阶段被实体化为 `collections` 表。

## 三、表结构（7 张表）

### 1. profiles 用户档案（1:1 扩展 auth.users）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | uuid | PK，FK → auth.users(id) ON DELETE CASCADE | 与登录账号共用同一 UUID |
| nickname | text | NOT NULL，CHECK 1～24 字 | 注册时自动取邮箱前缀 |
| avatar_url | text | | Storage avatars 公开 URL |
| bio | text | CHECK ≤ 140 字 | 一句话简介 |
| is_admin | boolean | NOT NULL DEFAULT false | 管理员标记 |
| created_at / updated_at | timestamptz | NOT NULL DEFAULT now() | updated_at 由触发器维护 |

### 2. series 系列

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | uuid | PK | |
| name | text | NOT NULL UNIQUE，CHECK 1～60 | 系列名 |
| slug | text | NOT NULL UNIQUE，CHECK `^[a-z0-9-]+$` | 路由标识，用于 /series/[slug] |
| description | text | CHECK ≤ 500 | 简介 |
| cover_url | text | | 封面 |
| created_by | uuid | FK → profiles(id) ON DELETE SET NULL | 创建者 |
| created_at / updated_at | timestamptz | | |

### 3. items 藏品条目

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | uuid | PK | |
| series_id | uuid | NOT NULL，FK → series(id) ON DELETE CASCADE | 所属系列 |
| name | text | NOT NULL，CHECK 1～80 | 藏品名 |
| category | text | NOT NULL，CHECK ∈ {figure,prize,badge,stand,charm,other} | 手办/景品/徽章/立牌/挂件/其他 |
| edition | text | NOT NULL DEFAULT normal，CHECK ∈ {normal,limited,reissue} | 普通/限定/再版 |
| msrp | numeric(10,2) | CHECK ≥ 0 | 官方参考价 |
| release_date | date | | 发售日期 |
| cover_url | text | | 封面 |
| created_by | uuid | FK SET NULL | 录入人 |
| **UNIQUE (series_id, name)** | | | 同系列下藏品不重名 |

### 4. collections 收藏记录（★ 核心中间表）

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | uuid | PK | |
| user_id | uuid | NOT NULL DEFAULT auth.uid()，FK → profiles ON DELETE CASCADE | 收藏人 |
| item_id | uuid | NOT NULL，FK → items ON DELETE CASCADE | 藏品 |
| status | text | NOT NULL DEFAULT wishlist，CHECK ∈ {owned,preorder,wishlist,sold} | 状态 |
| price | numeric(10,2) | CHECK ≥ 0 | 实际入手价 |
| currency | char(3) | NOT NULL DEFAULT 'CNY' | 币种 |
| source | text | CHECK ≤ 40 | 渠道 |
| purchased_at | date | | 入手日期 |
| note | text | CHECK ≤ 500 | 备注 |
| rating | smallint | CHECK 1～5 | 评分 |
| is_public | boolean | NOT NULL DEFAULT true | 是否晒谷 |
| created_at / updated_at | timestamptz | | |
| **UNIQUE (user_id, item_id)** | | | 防重复收藏 |

### 5. tags 标签 / 6. item_tags 藏品-标签关联

- `tags`：id、name（UNIQUE，1～20 字）。
- `item_tags`：item_id + tag_id 组成**联合主键**（无需代理键），双向 ON DELETE CASCADE。

### 7. item_images 藏品图片

数据库只存 `storage_path`（对象路径，UNIQUE），二进制放 Storage。含 alt（替代文本）、sort_order（排序）、uploaded_by。

## 四、设计理由（答辩重点）

1. **多对多必须拆中间表**：一件藏品被多人收藏、一人收藏多件，是典型 M:N。若在 items 上挂 owner_id，会数据冗余或只能支持一个收藏者。拆出 collections 后两侧都变成 1:N，items 保持唯一。

2. **中间表同时也是实体表**：collections 不只存两个外键，还承载状态、价格、渠道——「联系可以带属性」，不能把 M:N 当成纯路由表。

3. **主键用 UUID 而非自增 int**：不暴露业务量、不可枚举遍历、分布式不冲突。

4. **状态/分类用 CHECK 而非 enum 类型**：text + check 变更成本低（加值只改约束），PostgreSQL 的 enum 增删值要 ALTER TYPE，迁移更重。

5. **UNIQUE (user_id, item_id) 三层作用**：业务防重复收藏；技术防并发双击产生两行；性能上兼作组合查询索引。

6. **price 允许 NULL 而非 0**：预购/想入阶段尚无实际花费，NULL 表「尚未发生」，0 表「免费得到」，语义更准。

7. **is_public 解决「私人数据 vs 晒谷」矛盾**：同一记录本人永远可见，他人只见显式公开的；RLS 策略可写成「本人 or 公开」，无需另建晒图表。

8. **外键级联策略按业务语义选**：「从属数据跟随父数据删除」（藏品随系列、收藏随用户/藏品、图片随藏品 → CASCADE）；「公共数据与创建者解耦」（series.created_by / items.created_by → SET NULL）。

9. **视图必须 security_invoker**：PostgreSQL 15 之前视图默认以创建者权限执行，会绕过基表 RLS 导致统计泄露他人数据；`with (security_invoker = on)` 让视图按调用者身份执行策略。

10. **fn_is_admin 必须 security definer**：策略里直接查 profiles 判断管理员会因「查 profiles 又触发 profiles 策略」而递归；用属主函数读一次即可，且封装在单处。

11. **防自我提权（列级授权）**：profiles 允许本人更新，但必须 `grant update (nickname, avatar_url, bio)` 限制可更新列，否则用户可把自己 is_admin 改成 true 提权。

12. **collections 的 INSERT 用 with check 而非 using**：using 过滤「能看见哪些行」，with check 校验「写入的行是否合法」；只写 using 会让用户把 user_id 填成别人，往他人收藏夹塞数据——最典型越权漏洞。

## 五、Supabase 功能使用清单

| 功能 | 应用 |
|---|---|
| Auth | 邮箱注册/登录，session 管理 |
| Database | 7 表 + 外键 + CHECK/UNIQUE + 8 索引（含 GIN 三元组搜索索引） |
| RLS | 默认拒绝；公共数据可读、私有数据隔离；写按角色分层（见下） |
| 视图 | v_collection_stats / v_series_stats（均 security_invoker） |
| 函数 | fn_dashboard（一次 RPC 返回看板全部数据）、fn_is_admin |
| 触发器 | fn_handle_new_user（注册建档）、fn_touch_updated_at（时间戳） |
| Storage | covers（公开读/管理员写）、avatars（公开读/本人写，路径首段=uid 隔离） |
| 扩展 | pgcrypto（UUID）、pg_trgm（模糊搜索） |

## 六、RLS 策略矩阵（要点）

| 表 | 读 | 写 |
|---|---|---|
| profiles | 所有人（不含敏感字段） | 本人改昵称/简介/头像（列级授权，禁改 is_admin） |
| series / items / item_images | 所有人 | 仅管理员（fn_is_admin） |
| tags | 所有人 | 登录用户可加标签；改/删仅管理员 |
| item_tags | 所有人 | 仅管理员 |
| collections | 登录用户（本人 or is_public） | 仅本人（user_id = auth.uid()） |
| covers | 所有人 | 管理员 |
| avatars | 所有人 | 本人（路径首段 = uid） |

## 七、数据库与前端设计的对应关系

| 页面/组件 | 读取数据 | 写入 | 关联需求 |
|---|---|---|---|
| 首页系列卡片墙 | v_series_stats（名称/封面/藏品数） | 无 | FR-06 |
| 系列详情 | series + items（按 category 分组） | 无 | FR-07 |
| 藏品详情 | items + item_images + 公开收藏计数 | 无 | FR-08 |
| 加入收藏抽屉 | items 回显 | collections INSERT | FR-11/12 |
| 我的收藏列表 | collections join items join series | collections UPDATE/DELETE | FR-16 |
| 看板 | fn_dashboard() RPC | 无 | FR-19~22 |
| 晒谷墙 | collections（is_public=true） | 无 | FR-10 |
| 管理端 | series/items/tags | items/series/tags + Storage | FR-30~33 |
| 档案 | profiles | profiles + avatars | FR-03/04 |

## 八、建库步骤

1. Supabase 控制台 → SQL Editor → 粘贴 `supabase/schema.sql` 全文 → Run；
2. Settings → API 复制 anon key 填入 `index.html`；
3. 注册第一个账号 → 如需管理员：`update public.profiles set is_admin = true where id = '你的用户uuid';`
